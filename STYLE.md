# LGBTQIA+ Europe — style

`template.html` is the source; `index.html` is generated by `build.py` and must never be
hand-edited. The page began as a copy of [Bora y'all!]'s template, so that project's
STYLE.md still explains the layout, the type scale, the `.top` sticky trap and the touch
targets. This file covers only what differs here: the colour.

## Black and white, with ROYGBIV as the accent

The base is monochrome — white `#FFFFFF`, ink `#0E0E10` — so the rainbow is the only
colour on the page. That is the whole idea: if the interface were also coloured, ROYGBIV
would read as decoration. Kept to itself, it reads as meaning.

**Light only.** Dark mode was removed deliberately: the `@media (prefers-color-scheme:dark)`
block, the `:root[data-theme]` block and the theme toggle are all gone. Don't reintroduce a
dark theme without re-measuring every pair below against the new background.

### Where the rainbow appears

1. **The flagmark** beside the wordmark — seven stripes, the full spectrum.
2. **The rule under the header** — a 3px left-to-right spectrum via `border-image`.
3. **The category system** — seven category families, seven hues, in ROYGBIV order:
   music → red, stage → orange, art → yellow, street → green, table → blue,
   doing → indigo, pride → violet. `other` is grey, not a hue.

Nothing else. The wordmark stays ink, the buttons stay black, the day rules stay black.

### Two variables per hue, and why

Each family has `--c-<family>` **and** `--c-<family>-v`:

- `--c-<family>` is **text-safe**, tuned to clear 4.5:1 on white. Used for the category
  label on a card and the weekday under the date.
- `--c-<family>-v` is the **vivid** flag hue, used only as a fill or border — the chip dot
  and the 3px rule beside the date.

This split exists because a real rainbow cannot survive a contrast requirement. Flag yellow
`#F5C518` is **1.63:1** on white — invisible as text. Forced up to 4.5:1 it becomes a deep
gold `#8E7209`, which is legible but no longer looks yellow. So the vivid hue carries the
colour where nothing binds, and the tuned hue carries the text. Same lesson as the parent
project's mustard rule, applied to all seven.

**Never use a `-v` value as a text colour.**

### Pills are measured against the pill, not the page

`--free` and `--paid` sit on tinted chips (`--free-soft`, `--paid-soft`), not on white. A
green that passes on white can still fail on a pale green chip — the first version did,
at 4.16:1. Both are now tuned against their own background. If you change a `*-soft`
value, re-measure its text colour.

## The check before shipping a colour change

Render at 1440 / 834 / 390 and confirm:

1. **Zero AA failures.** Measure, don't eyeball — walk every element with a text node,
   resolve its real background through transparent ancestors, and compute the ratio.
   The current palette measures 79 pairs across three widths with 0 failures.
2. `[...document.querySelectorAll('.ev .top')].filter(e=>getComputedStyle(e).position==='sticky').length` is **0**.
3. No horizontal overflow, and no control under 44px at 390px. Desktop keeps its compact
   chrome on purpose, so it reports controls under 44px — that is expected, not a fault.
4. No page errors in the console, and the event list actually renders. A JS error leaves
   the static placeholder headline in place, which is easy to mistake for a styling bug.
